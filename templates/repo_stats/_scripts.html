{# Repository Statistics — Chart.js rendering. Data arrives via the #repoStatsData JSON block so no server values are interpolated into JS. Theme changes rebuild the charts rather than mutating them, because neither alternative works: * Writing into `chart.options.*` mutates a resolved-options proxy. The `opts.plugins.legend.labels = opts.plugins.legend.labels || {}` idiom reads a value out of that proxy and assigns it back into itself, which builds a self-referential chain and blows the stack on the next update. * Setting only `Chart.defaults.*` and calling update() leaves the charts stale: per-scale options are resolved once at construction and cached, so tick and grid colours keep their original theme's values. That is invisible until you actually switch themes — the first paint is right. Destroying and recreating is cheap here (three static charts, no polling) and is the only option that is correct in both directions. #}
