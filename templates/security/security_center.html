Host-Firewall Enforcement (fail2ban)

There is one ban list — the Global Ban List tab. fail2ban is an optional firewall enforcer for it: when enabled, every application ban (manual or automatic) is also dropped at the host firewall, before traffic reaches the web app. You still add, remove, and review web bans on the Global Ban List tab — nothing to manage twice here.

Configuration

When on, the IPs on the Global Ban List tab are also blocked at the host firewall (all ports). The application-level ban always applies regardless of this setting; this only adds firewall-level blocking.
Optional: fail2ban watches the system's SSH log and bans brute-force attempts the web app can't see. Because an IP hammering port 22 is a bad actor everywhere, these offenders are automatically added to the global ban list (Global Ban List tab) and blocked at all ports. They're also listed below; unbanning there clears them globally.

Security Checkup

Checks this host's baseline hardening — the host firewall and fail2ban's ban-list enforcement — and offers a one-click fix for anything that's missing. Built after finding a real deployment silently running with no host firewall at all: update.sh only updates the application, it never re-runs the one-time firewall setup install.sh performs on a fresh install (added in v2.19.7) — so a deployment provisioned before that version, or one where the firewall was later removed, stays exposed through every subsequent update with nothing to flag it. Run this after every update if you're not sure.

Privacy

Mask the address at capture time (IPv4 last octet / IPv6 host bits zeroed) so a raw visitor IP is never stored. Local/loopback addresses are left intact. GDPR-friendly; reduces the precision of the Visitors and Map reports.
Anonymize keeps the rows but masks the IP & hostname (counts stay intact). Purge permanently deletes every recorded request for that IP. Honours data-subject erasure requests without shell access.
